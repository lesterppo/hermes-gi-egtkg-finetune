# Base vs LoRA adapter — held-out A/B evaluation

Date: 2026-09-13 · Adapter: `results-2026-09-12` (step-374, continuous daily QLoRA)
Base: `NousResearch/Meta-Llama-3.1-8B-Instruct` (NF4, same session) · Hardware: free Colab T4
Decoding: greedy (`do_sample=False`) · Harness: `eval_ab.py` / `eval_build.py` / `ab_score.py` / `judge_ab.py`

## Method (why the numbers are trustworthy)

- **Held-out by construction.** The eval rows are built ONLY from articles whose
  PMID is absent from the training knowledge store: a fresh 60-day PubMed ingest
  yielded 2000 PMIDs / 1860 with abstracts, of which **248 were unseen**; the
  training store had 1989 PMIDs. Rows come from those 248 articles only.
- **Same prompt, same weights, one variable.** Adapter ON vs
  `model.disable_adapter()` OFF, identical greedy decoding, identical prompts.
- **Blinded third-party review.** 14 comparisons (7 kg / 4 evidence / 3 fact) were
  sent to Gemini Pro with the answers labelled A/B in randomized order; the
  judge never saw which side was the fine-tune.
- Eval rows were generated by the pipeline's own builder (`egtkg_build.py`),
  so the question shapes match training exactly.

## Verdict

- **Extractive rows: the fine-tune works, decisively.** Given the span in the
  prompt it reproduces it verbatim (recall 1.00), attaches provenance 100% of the
  time (base: 2%), invents almost nothing (0.2–0.0% out-of-evidence words) and
  never truncates. Judge: 5/5 grounded, 7/7 preferred.
- **`kg` rows: the adapter is actively harmful.** On relation questions where the
  evidence is NOT in the prompt, it emits the trained shape with a fabricated
  study, PMID and disease context. Only 4/7 preferred, grounded 1.29 vs base 1.57.
  This is a row-design defect, not a tuning one: the task asks the model to recall
  a specific article's finding from a relation question it was never given the
  evidence for, so the only way to satisfy the loss is to hallucinate plausible
  evidence.
- **The loop had also stopped learning.** `pubmed_ingest` was crashing on
  non-numeric store keys (textbook `SP_…`, case-report `CR_…`) at the final write
  step, so every run since the reference corpus landed ingested ZERO new
  literature while the job stayed green (rows pinned at ~1490). Fixed in `5a9bc54`
  (`write_store`/`_sort_key`, keyed `merge_stores`, `INGEST_STATUS` surfaced into
  metrics/result.json), verified: fresh 60-day ingest now exits 0 with 248 new
  articles.

## Recommended close-out (do NOT freeze this adapter as-is)

1. Drop `kg` rows, or rewrite them so the evidence span is in the prompt (making
   them extractive like the other two types). Add abstention rows — "the
   retrieved evidence does not answer this" → "Not answerable from the retrieved
   evidence" — which the current mix has none of, so the model cannot decline.
2. Let the (now fixed) ingest run a few days so the corpus actually grows, with
   `ingest_ok` asserted in `result.json`.
3. Re-run this eval as the gate. Freeze + archive + disable cron when: extractive
   kinds stay 5/5 grounded AND the relation/abstention behaviour is either removed
   or ≥4/5 grounded.
